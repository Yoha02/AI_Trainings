# A search result is not an answer

**One learning outcome:** decide whether retrieved passages actually support an answer before asking a language model to write one.

This short exercise uses a fictional, two-page shop handbook. You will inspect three questions, including one whose answer the handbook does not provide. Allow about ten minutes **after** installing the repository's dependencies.

The exercise extracts a PDF, embeds the text locally, and searches an in-memory Qdrant collection. It makes no Google or other language-model requests, needs no API key, and explicitly uses local storage even if `QDRANT_URL` is set. The first run can download the public embedding model; this is not a fully offline first-time setup.

## 1. Read the source first

Open the [sample PDF](../data/sample_handbook.pdf) or its [plain-text source](../data/sample_handbook.txt). Before running anything, write down which page could support each answer:

| Question | Evidence to look for | What a supported answer can say |
|---|---|---|
| How long is the return window? | Page 1: unused items, 30 days, receipt | Unused items may be returned within 30 days of purchase with a receipt. |
| How long does standard delivery take? | Page 2: 3 to 5 business days | Standard delivery takes 3 to 5 business days. |
| What is the international shipping policy? | Page 2 explicitly says the handbook contains no international shipping policy | The handbook does not specify it. This does **not** establish that the shop refuses international orders. |

These are expectations written from the source, not answers generated by the script.

## 2. Run the evidence viewer

Follow [Start locally](../README.md#start-locally) to create the environment and install dependencies. You can skip Google-backend setup for this exercise. From the repository root, run:

```sh
python scripts/retrieval_walkthrough.py
```

If PowerShell activation is unavailable, use `.venv\Scripts\python.exe` instead of `python`.

For each question, the output prints ranked passages, their page numbers, and cosine-similarity scores. The final line is the lesson's checkpoint:

```text
Similarity ranks passages; it is not a confidence or support verdict.
```

Read the passages themselves. In the sample run, the first result was page 1 for the return question and page 2 for the delivery and international-shipping questions. Scores can vary slightly across environments. There is no universal score cutoff in this lesson that proves an answer is supported.

## 3. Inspect the unanswered question

The international-shipping question still receives search results. Retrieval finds nearby text; it does not promise that the document contains a policy.

Compare these possible responses:

- **Supported:** "This handbook does not specify an international shipping policy."
- **Unsupported:** "The shop ships internationally within 3 to 5 days."
- **Also unsupported:** "The shop does not ship internationally."

The second response borrows a real delivery duration and applies it to an unsupported scope. The third turns missing information into a prohibition. Both errors can sound plausible even if accompanied by a page citation.

## 4. Change one setting

Retrieve only one passage:

```sh
python scripts/retrieval_walkthrough.py --k 1
```

Then try smaller chunks:

```sh
python scripts/retrieval_walkthrough.py --chunk-size 200 --overlap 40
```

Compare the evidence: did the return conditions stay together, or was a needed condition left in another chunk? Does the first result still support the same answer? Keep your question fixed while comparing settings.

To try your own question or save the evidence:

```sh
python scripts/retrieval_walkthrough.py --question "Can I return opened food?" --k 1
python scripts/retrieval_walkthrough.py --json > evidence.json
```

The JSON includes questions, settings, passages, page numbers, and scores. It deliberately contains no generated answers or automatic support labels. The in-memory index closes when the script exits.

## 5. Take the same habit into a Gemini application

Continue with [Lab 3](../Lab3_RAG_PDF_Chatbot.ipynb) when you want to add generation. That lab uses a Google backend and can incur API usage; its setup is separate from this local exercise.

## Troubleshooting

| Symptom | Next step |
|---|---|
| Missing Python package | Install `requirements.txt` using the same Python interpreter that runs the script. |
| First embedding load is slow or cannot download | Allow the public model download, or use an environment with the model already cached. No Google login is needed. |
| Scores differ from someone else's run | Compare the source text and page ranks first. Small numeric differences alone do not change what the document says. |
| Invalid chunk-size/overlap error | Use a positive chunk size and `0 <= overlap < chunk_size`. |
| A custom question gets an irrelevant passage | That is useful evidence of a retrieval limitation. The script has no answerability classifier and can return the nearest passage even when it is unhelpful. |

Have a different result? Share the question, settings, and retrieved passages in [learner Q&A](https://github.com/Yoha02/AI_Trainings/discussions/new?category=q-a). Include the revision shown by `python scripts/lab_status.py`. Questions and corrections are welcome.

The new walkthrough was checked locally with Python 3.13 on Windows using real PDF extraction, local embeddings, and in-memory Qdrant. Its regression checks reject any attempt to construct a Google client, generate an answer, or use the configured hosted-Qdrant factory. These checks do not evaluate a language model.
